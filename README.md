# 糖心志者

糖心志者是一个 Chrome Manifest V3 浏览器插件，用可爱的「糖果手帐」工作台和「沉浸糖果影院」承载安全账号池、智能播放、视频下载、服务体检、版本更新和缓存整理能力。

## 项目介绍

界面源码位于 `ui-src/`，通过 Vite 打包为 `dist-ui/txzz-ui.js` 和 `dist-ui/txzz-ui.css`，再由 `manifest.json` 作为内容脚本加载。`content.js` 继续承担页面集成，通过事件状态桥把账号池、播放详情、下载和更新状态交给 React；React 端已经拆为领域规则、跨页视图模型、偏好 Hook、工作台壳层、页面组件和设计令牌，页面不再自行重复解释后台状态。

插件默认只显示左上角短时流程气泡和右下角「糖糖」伙伴入口，不遮挡网站主体。点击伙伴后展开糖果手帐工作台：桌面端使用浅色手帐侧栏与独立工作区，移动端使用全屏面板和安全区底栏；今日总览、账号小屋、放映室、下载收纳篮和照料中心保持统一信息层级与操作反馈。

当前源码与正式 CRX 均为 `5.0.3`（构建 `2026-07-27-1230`），继续使用 4.0.0 已启用并妥善保留的正式私钥，扩展 ID 保持为 `ddefadnhgebdclpkabeobjidjllkdkhm`，因此 4.0.0 及 5.0.x 用户可原位覆盖升级。更早的旧 ID `ghbbddahmhhmjknofkmdkcflbmplcace` 因原私钥永久丢失，仍需先移除旧扩展再安装当前版本。

- 旧实验播放器：v3.0.0 起已清理 XGPlayer / xgplayer-hls 实验链路，当前构建只保留 ArtPlayer + hls.js，减少依赖冲突和构建风险

- 远程服务：Cloudflare Worker
- 云端数据库：Supabase
- 部署工具：Wrangler `4.110.0`
- 视频转封装：`mux.js@7.0.0`
- 文件编码：UTF-8

## 核心功能

- 伙伴入口：默认只显示「糖糖」CSS 伙伴和左上角流程气泡，支持桌面端和移动端拖动；位置会限制在可视区域并持久保存，避免拖出屏幕后无法找回。
- 糖果手帐工作台：莓果粉、薰衣草、薄荷和杏子色只承担动作与状态，暖白底负责长时间阅读；桌面端使用浅色手帐侧栏，移动端转为全屏工作区和安全区底栏。
- 业务分层：`domain/` 管理账号与下载规则，`model/` 统一导航与跨页状态推导，`playback/` 管理播放会话 reducer、媒体内核、线路策略、续播和全屏控制，`hooks/` 管理通用偏好，`components/layout/` 负责壳层；页面只消费统一 ViewModel。
- 五个业务空间：导航重命名为今日总览、账号小屋、放映室、收纳篮和照料中心，底层动作与 Worker 接口保持兼容。
- 今日总览：按「今日运行清单 → 正在进行 → 快捷动作 → 小日记」组织内容，优先告诉用户当前风险与下一步，而不是只罗列统计数字。
- 页面状态展示：集中展示会员状态、扩展运行状态、账号池状态和最近流程。
- 播放状态展示：宽屏采用「播放器主舞台 + 本场影片侧栏」，片源、下载和足迹收纳在独立抽屉；窄屏自动改为单栏。解析、账号轮换和安全解锁使用可见步骤条，资源就绪后仍保持暂停，必须由用户点击「开映」。
- 账号池管理：账号池页重构为控制台布局，支持账号搜索、本地可靠编辑、删除二次确认、云端自动轮换和云端优先本地兜底。
- 云端轮换策略：云端账号按金币数量升序排序；获取播放详情失败或金币视频处理失败时自动切换下一个云端账号。
- 金币视频策略：先检查主线路和备用线路；VIP 等账号已经返回可播放链接时立即使用，绝不调用购买接口。无扩展名签名地址、相对播放地址同样按有效线路处理；只有确实没有链接且仍为金币锁定时，才从金币最少账号组中随机选择一个账号购买。
- 云端账号卡片：统一展示账号昵称、可用状态、不可用原因、普通 VIP、尤物圈和金币余额；云端账号不提供手动选择按钮，只参与自动轮换；失效云端账号默认隐藏，可手动查看。
- 云端分类识别：前端账号池页面和后台统一识别 `cloudReadonly`、`isCloud`、`remoteId`、`cloudId`、`source=remote`、`source=qrcode` 等云端摘要标记，避免云端账号误显示到本地账号分类。
- 账号可用判定：账号池会区分账号凭据错误和视频资源异常，视频下架、播放详情缺少链接或临时接口异常不会把有成功检查记录的云端账号误判为失效。
- 关键流程提示：插件运行时会在页面左上角显示轻量流程标签，只展示同步账号池、云端账号轮换、当前使用账号、金币解锁、获取播放状态、下载合并、保存到设备和异常等关键状态；被动网络观察只写入诊断记录，不再反复弹出，正常操作提示约 3.2 秒后自动关闭。
- 添加账号面板：通过「添加账号」按钮展开，支持账号密码、账号凭证、token/deviceId 三种本地保存方式。
- 远程同步：通过 Cloudflare Worker 读取 Supabase 账号池，扩展后台自动携带与 Worker 配套的内置 Bearer 访问密钥；用户只需填写服务地址，页面环境只看到脱敏摘要。
- 云端服务体检：设置页通过扩展后台检测 `/v1/diagnostics`、`/v1/status` 和 `/v2/health`；v2 健康检查同时验证播放安全迁移是否就绪，再次打开时会按 Worker 地址展示匹配的上次体检结果。
- 体检快捷处理：体检结果下方提供「处理账号池」「同步账号」「复制报告」三个快捷操作，可直接跳转账号池、打开失效账号视图或复制完整体检报告。
- 播放页面：扩展只调用 Worker `POST /v2/playback/session`，把服务端线路决策、账号与获取摘要转成单一 `screening` 状态。页面编排与媒体生命周期完全分离：单 reducer 管理 `idle → resolving → ready → loading → playing/paused → buffering/switching → ended/error`，每个异步事件携带会话代次；任意时刻只保留一个 ArtPlayer `5.4.0` 和一个 hls.js `1.6.16` 实例。线路策略综合服务端健康度和实际播放反馈，起播超过 8 秒、30 秒内累计 3 次 HLS 致命错误或恢复失败时只自动切一次尚未尝试的备用线路，并保留进度、暂停状态、音量、倍速与画面模式。续播按视频编号每 5 秒保存，15 秒以内、距结尾不足 30 秒或超过 30 天的记录不会恢复。完整功能矩阵见 [`docs/player-system.md`](docs/player-system.md)。
- 下载管理：接管视频详情页下载按钮并创建后台任务；下载页支持筛选、搜索、排序、失败摘要和任务详情。批量保存、复制链接、复制报告、批量重试、打开下载目录和清空任务统一收纳到「更多操作」菜单；失败重试带节流保护，清空任务和缓存均使用单一确认弹层，避免重复触发。
- MP4 输出：M3U8 分片下载完成后优先转封装为真实 MP4，失败时保留 TS 兜底。
- 数据清理：设置页通过明确的「完整重置」操作清除旧版本缓存、账号池缓存、播放缓存、下载缓存、更新缓存和页面运行缓存，不再使用容易误解的假复选框。
- 设置分类：云端服务、体验功能、版本升级和数据管理使用分类导航，低频与高风险操作不再挤在同一长页面。
- 旧数据迁移：首次升级到 5.0.0 时会把旧 `fullDetails` 转换为新的放映历史；账号池、下载记录和设置保持不变。购买防重复账本与 `screening` 使用独立 schema，旧格式只迁移一次，不会覆盖新会话。
- 更新管理（升级系统 v7）：后台并发读取固定仓库路径下的多份 `update.json`，先用内置正式公钥验证完整清单签名，再按 **version + build + 来源优先级**选取最新；任意镜像无法伪造版本或把地址改到其他仓库。自动检测复用 15 分钟成功缓存，手动检测和下载前检测实时绕过，不同任务契约分别去重，所有状态通过串行队列写入。安装包只发起一次完整请求，同一份内存字节必须通过大小、SHA-256、CRX3 结构、正式扩展 ID 和包自身 RSA 签名校验；随后由离屏页生成 Blob，拉起浏览器保存对话框并确认下载任务真实创建，避免文件头探测与实际下载之间被替换。升级中心与检测弹窗共用真实阶段，明确区分检测、已提交下载和手动安装；忽略提醒按更新 ID 持久化且失败可见。完整信任链见 [`docs/update-system.md`](docs/update-system.md)。
- 响应式适配：手机视图使用安全区底部导航和独立内容滚动，桌面视图使用侧栏工作区；插件采用独立尺寸基准，不受宿主网站根字号缩放影响。最终版本在真实网站以 `320`、`390`、`640`、`1024`、`1536` 像素宽度检查布局，并支持系统减少动态效果设置。

## 安装教程

### 方式一：安装 CRX（推荐，更新也下这个）

1. 下载最新安装包：  
   `https://github.com/lsy5920/tangxin-zhizhe-extension/raw/main/releases/tangxin-zhizhe-latest.crx`
2. **Kiwi 浏览器（安卓）**：下载后点开 `.crx` 即可安装/更新。
3. **Chrome / Edge 桌面端**：
   - 打开 `chrome://extensions/`（或 `edge://extensions/`）
   - 打开右上角「开发者模式」
   - 把 `.crx` 文件拖进扩展页面完成安装  
   - 若浏览器拦截「非应用商店扩展」，请用下方「方式二」加载解压目录，或允许来自其他来源的扩展（视浏览器策略而定）
4. 以后在插件「设置 → 升级中心」点「下载」也会直接下载同款 `.crx` 文件。

### 方式二：开发者模式加载源码目录

1. 打开 Chrome 或 Edge。
2. 在地址栏输入 `chrome://extensions/` 并回车。
3. 打开右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」。
5. 选择当前目录：`tangxin-zhizhe-extension`。
6. 如果刚修改过界面源码，先在当前目录执行 `npm ci`，再执行 `npm run check` 生成并验证 `dist-ui/`。
7. 初次只使用已构建好的插件时，可以直接加载当前目录；如浏览器提示缺少 `dist-ui/txzz-ui.js`，说明需要先执行上一步构建命令。
8. 打开需要联调的页面。
9. 页面右下角出现「志」字悬浮球，表示插件加载成功。

## 远程账号池配置

推荐使用远程账号池保存账号凭据。账号密码、二维码凭证、token、deviceId、Supabase `service_role` 等敏感信息应放在 Cloudflare Worker 或 GitHub Secrets 中。插件后台只保存 Worker 地址；服务访问密钥已与对应 Worker 一起内置，用户无需填写，React 页面不会获得密钥明文。

配置步骤：

1. 点击「志」字悬浮球打开面板。
2. 进入「账号池」页。
3. 在「云端连接」中填写「云端服务地址」。
4. 选择账号来源模式。
5. 点击「保存并验证」，插件会自动使用内置访问密钥。
6. 点击「同步云端」读取云端账号池。
7. 云端账号默认只显示可用账号；需要排查坏账号时，打开「查看失效」。

账号来源模式说明：

| 模式 | 说明 |
| --- | --- |
| 云端轮班 | Worker 按金币数量从少到多选择可用账号，失败时自动切换下一个账号。 |
| 本地值班 | 只使用插件本地保存并选中的账号。 |
| 云端优先，本地兜底 | 优先使用云端账号，失败后尝试本地账号。 |

## 使用教程

### 打开和关闭面板

1. 打开目标页面。
2. 点击右下角「糖糖」伙伴入口。
3. 伙伴入口隐藏，工作台展开，默认进入上次使用的页面。
4. 点击关闭按钮后，工作台收起，伙伴入口重新出现。
5. 按住伙伴入口拖动可调整位置；位置会自动限制在屏幕内并保存，窗口变化时也会重新校正。
6. 点击主界面右上角「关于」按钮，可打开项目主页。
7. 桌面端通过左侧导航切换页面，手机端通过底部导航切换页面。
8. 进入网站视频详情页时，插件会阻止网页视频自动播放并默认暂停；点击播放器区域或播放按钮后可正常播放。

### 应用页面状态展示

1. 打开插件面板。
2. 点击「应用展示覆盖」。
3. 面板会刷新当前状态区域。
4. 如果页面内有对应状态展示，插件会同步进行页面侧显示更新。

### 查看播放状态

1. 打开任意视频详情页或播放页。
2. 插件会自动记录最近视频和播放处理状态。
3. 进入「放映室」查看播放器主舞台、本场影片侧栏，以及片源、下载、足迹三个抽屉页签。
4. 侧栏步骤条会显示影片识别、账号轮换、跳过或执行金币解锁、送达放映线路等真实阶段；有直链时购买阶段明确标记为跳过。
5. 资源就绪后默认暂停，点击中央「开映」或控制栏播放按钮才会开始；空格/K 同样可播放或暂停。
6. 点击「重新检票」会使用新的 `requestId` 请求 Worker v2 会话，重新评估缓存、账号、线路和获取方式，不会创建下载任务。
7. 片源抽屉提供完整链接复制、打开和下载；足迹按视频会话展示迁移后的历史，不再与播放器高频控制同权平铺。
8. 播放器使用 ArtPlayer + hls.js；线路卡和播放器设置均可手动换线，自动切线只会选择本场尚未自动尝试过的线路。
9. 在插件播放页点击全屏时，会优先请求浏览器全屏；如果浏览器只能让插件宿主全屏，会自动进入播放全屏模式，隐藏面板外壳、侧栏、标题栏、底部导航和其它播放页卡片，播放器外层会同步无框覆盖整个视口，视频内容默认按原比例尽可能完整显示；如果浏览器拒绝真实全屏，会自动使用插件内沉浸全屏兜底。
10. 播放器进入全屏后，顶部会显示全屏来源、视口覆盖率和容器贴合体检；如果出现圆角、内层视频框、裁剪或宿主全屏模式异常，可点击「诊断」在页内查看报告，报告会包含播放器容器尺寸、当前视口尺寸、覆盖率和异常原因。
11. 播放器内置进度条可点击跳转定位；视频画面默认只显示播放/暂停、后退、前进、菜单和全屏主控按钮，全屏时会额外显示「锁定」按钮；全屏控制层改为贴底渐变沉浸样式，进度手柄常显，音量/亮度/快进快退会弹出大图标手势反馈；顶部诊断徽标短时显示后自动收起；锁定后只保留右下角解锁按钮，双击左右仍可快退快进；播放稳定后控制层会自动隐藏；单击视频画面会显示悬浮 UI，再次单击会隐藏顶部状态条和底部控制面板，全屏观看时鼠标也会自动隐藏。
12. 点击「菜单」可展开二级菜单，再按「线路」「显示」「声音」「工具」分组使用功能；线路组负责推荐、主线、备用切换和状态查看，显示组负责倍速、横屏/竖屏比例、原比例完整显示、铺满、裁满、HLS 清晰度、备用线路、截图和快进步长，声音组负责静音、音量滑块、亮度滑块、音量记忆和亮度记忆，工具组负责重载、画中画、复制完整链接、打开完整链接、下载视频和查看诊断报告。
13. 播放器支持键盘热键、截图、画中画、网页全屏、浏览器全屏、系统媒体键、双击左右快进快退、移动端手势和移动端长按快进；空格或 K 播放暂停，左右方向键按当前步长快退快进，上下方向键调音量，M 静音，F 全屏；上次未看完的视频会自动恢复到上次进度。
14. 如果播放器卡住或换线后没有刷新，在「菜单」的「工具」里点击「重载」重新载入当前播放源。
15. 如果主线路播放不稳，在「菜单」的「显示」里点击「备用」一键切到备用线路；播放异常时插件也会自动尝试切换备用线路。
16. 如果觉得快进快退幅度不合适，在「菜单」的「显示」里点击当前步长按钮，可在 5 秒、10 秒、30 秒、60 秒之间循环切换。
17. 如果全屏后两侧有黑边，这是为了保持原比例完整显示；在「菜单」的「显示」里点击「原比例」按钮，可在「原比例」「裁满」「铺满」之间循环切换，其中「裁满」会占满屏幕但可能裁切边缘，「铺满」不留黑边但可能轻微变形。
18. 如果网页视频偏暗或偏亮，在「菜单」的「声音」里拖动「亮度」滑块，可在 60% 到 140% 之间调整，插件会自动记住亮度偏好。
19. 点击完整播放器右键菜单里的「复制完整链接」「打开完整链接」「查看播放器诊断」，可快速排查当前播放源和全屏容器状态。
20. 点击完整播放器外层或「菜单」的「工具」里的「复制」会复制当前播放源完整链接，点击「打开」会用补全域名后的完整链接在新窗口打开当前播放源。
21. 点击「打开线路」或主备线路卡片里的「打开」，也会用补全域名后的完整链接在新窗口打开当前线路，方便直接验证主线路或备用线路是否能播放。
22. 如果当前视频支持下载，可直接点击「下载视频」创建下载任务。
23. 创建下载任务后，播放页会显示当前视频的下载阶段、分片进度、文件大小、更新时间和完整源链接摘要。
24. 当前视频下载卡片可直接复制完整下载源链接；如果任务失败，可直接点击「重试下载」重新创建任务。
25. 足迹抽屉可把任意历史会话载入主舞台预览；该会话始终使用自己的视频编号、线路和决策，不会串用当前影片数据。
26. 下载合并完成后，可在放映室或收纳篮保存到设备；失败任务仍可在收纳篮重试和查看报告。

### 管理账号池

1. 进入「账号池」页。
2. 顶部统计区会显示全部账号、云端可用账号、本地账号和失效账号数量。
3. 云端账号卡片统一显示账号昵称、可用状态、不可用原因、普通 VIP、尤物圈和金币余额。
4. 失效云端账号默认隐藏；打开「查看已失效云端账号」后可以查看不可用账号和失败原因。
5. 搜索框可按账号名称、用户名、编号或备注同时筛选云端和本地账号。
6. 点击「添加账号」会先弹出类型选择窗口。
7. 选择「账号密码」后，只显示账号昵称、用户名和密码等必填内容。
8. 选择「账号凭证」后，只显示账号昵称和账号凭证内容。
9. 选择「token/deviceId」后，只显示账号昵称、deviceId 和 userToken。
10. 点击「保存本地」只保存到插件本地账号池。
11. 点击「保存并上传云端」会把账号提交给 Worker 加密保存。
12. 上传成功后，同步回来的云端卡片会继续显示账号昵称、凭据类型、可用状态、不可用原因、普通 VIP、尤物圈和金币余额。
13. 本地账号卡片可选择、编辑、检查、上传云端或删除；编辑时凭据留空会保留后台原值，删除前必须二次确认。云端账号只显示摘要，不能手动固定或修改凭证明文。

### 下载视频

1. 打开视频详情页。
2. 点击页面上的下载或缓存按钮。
3. 插件会创建后台下载任务。
4. 如果是 MP4 直链，会直接进入可保存状态。
5. 如果是 M3U8，会先下载分片，再合并并优先转封装为 MP4。
6. 进入「下载」页查看进度。
7. 任务较多时，可点击「全部」「进行中」「可保存」「失败」快速筛选。
8. 可在搜索框输入标题、视频编号、任务编号、阶段、失败原因或链接，进一步缩小当前筛选结果。
9. 可切换「最近」「失败优先」「进度」「大小」排序，排序会影响当前可见列表和复制报告顺序。
10. 如果当前范围里有失败任务，页面会显示失败原因概览，按原因聚合数量，方便先处理高频问题。
11. 点击「失败摘要」会复制当前范围里的失败原因、视频编号和完整源链接。
12. 下载任务卡片会显示完整源链接摘要，点击复制按钮会复制包含 `https://域名/...` 的完整下载源链接。
13. 点击「复制筛选链接」会批量复制当前筛选、搜索和排序结果中的完整下载源链接，每行一个链接。
14. 点击「复制报告」会复制当前筛选、搜索和排序后的任务状态、格式、进度、文件大小、更新时间、失败原因和完整源链接。
15. 如果任务失败，可在失败任务卡片点击「重试」重新创建同一视频的下载任务。
16. 切换到「失败」筛选后，可点击「重试失败」按视频编号去重批量重新创建当前结果中的失败任务。
17. 切换到「可保存」筛选后，可点击「保存全部」逐个处理当前结果里的待保存任务。
18. 合并完成后点击「保存到设备」。

### 管理下载任务

「下载」页支持：

- 查看总任务、进行中、已完成和失败数量。
- 按全部、进行中、可保存和失败快速筛选下载任务。
- 按标题、视频编号、任务编号、阶段、失败原因和链接搜索下载任务。
- 按最近更新、失败优先、进度最高和文件大小重排当前结果，方便优先处理失败、接近完成或大文件任务。
- 按当前可见任务聚合失败原因，并可复制失败摘要用于排查。
- 一键保存当前筛选和搜索结果中的全部可保存任务，已保存任务不再占用可保存数量。
- 批量复制当前筛选、搜索和排序结果中的完整下载源链接。
- 复制当前筛选、搜索和排序任务报告，用于排查失败原因、核对分片进度和保存完整源链接。
- 失败任务可直接点击「重试」重新创建同一视频的下载任务。
- 失败筛选下可点击「重试失败」批量恢复失败任务。
- 查看视频名称、视频编号、输出格式、文件大小和更新时间。
- 查看完整源链接摘要，并复制包含域名的完整下载源链接。
- 保存单个任务到设备。
- 删除单个任务卡片和缓存。
- 打开浏览器下载目录。
- 清空当前任务记录。

### 云端服务体检

1. 打开插件面板。
2. 进入「设置」页。
3. 点击「开始体检」。
4. 插件会优先访问 `/v1/diagnostics`，如果云端服务尚未升级，会自动降级检测 `/v1/status` 和 `/v1/health`。
5. 体检结果会显示总分、整体摘要、分项检查、账号池摘要、服务端建议动作和建议下一步。
6. 如果体检提示账号池为空，可回到「账号池」页上传账号或同步云端。
7. 如果体检提示缺少密钥，需要在 Cloudflare 或本地 `.dev.vars` 中补齐后重新部署。
8. 点击「处理账号池」会自动跳转到账号池页；如果体检发现异常账号，会自动打开失效账号视图。
9. 点击「同步账号」可直接重新同步云端账号池。
10. 点击「复制报告」可把体检结果、账号池摘要、分项检查、建议和服务端建议动作复制到剪贴板，便于保存或排查。
11. 重新打开设置页时会显示当前云端服务地址对应的「上次体检」，可点击「清除上次体检」移除本地历史记录；清除操作不会影响云端账号池和 Worker 服务。

## 视频格式说明

插件处理 M3U8 时不会只改文件后缀，而是使用 `mux.js@7.0.0` 对 TS 分片合并结果进行转封装：

- 转封装成功：输出 `.mp4`，MIME 为 `video/mp4`。
- 转封装失败：保留 `.ts` 兜底文件，并在任务卡片显示失败原因。

## 本地账号上传云端

1. 进入「账号池」页。
2. 填写本地账号信息。
3. 点击「保存并上传云端」，或在本地账号卡片上点击「上传云端」。
4. 上传成功后，插件会同步云端账号池。
5. 已上传账号会转为云端摘要展示，不能在插件前端查看或修改凭证明文。

## 清除旧数据缓存

5.0.0 覆盖安装不会自动清空运行数据：旧 `fullDetails` 会转换为新的放映历史，账号池、下载任务、Worker 地址和更新设置继续保留。只有购买防重复账本和 `screening` 会升级到新 schema；如果确实需要手动清理：

1. 打开插件面板。
2. 进入「设置」页。
3. 打开「数据管理」分类并点击「完整重置」。
4. 阅读影响范围后点击「确认重置」，完成后刷新页面。

清理范围包括：

- 插件本地账号池缓存
- 远程账号池摘要缓存
- 播放状态缓存
- 下载任务缓存
- 更新检测缓存
- 页面监听运行缓存
- 旧版本默认配置
- 旧默认空种子账号
- 旧测试播放详情缓存

## 常见问题排查

### 页面没有出现悬浮球

1. 确认加载的是 `tangxin-zhizhe-extension` 目录。
2. 确认浏览器扩展页没有报错。
3. 刷新页面。
4. 检查当前页面地址是否匹配 `manifest.json` 的 `matches` 配置。

### 手机端点击按钮无效

1. 刷新页面后重试。
2. 确认没有旧版本插件同时启用。
3. 检查页面是否被其他浮层遮挡。
4. 尝试关闭面板后重新点击悬浮球展开。

### 刷新后仍然看到旧页面

1. 在浏览器扩展管理页点击当前插件的「重新加载」按钮。
2. 确认加载目录中存在 `dist-ui/txzz-ui.js` 和 `dist-ui/txzz-ui.css`。
3. 重新打开或刷新目标页面，不要只刷新扩展管理页。
4. 当前版本已经删除旧 DOM 面板、旧流程浮层和旧更新弹窗；如果仍看到旧面板，通常是浏览器还在运行旧扩展实例，关闭重复安装的旧版本后再刷新页面。

### 构建提示 vite 不是内部或外部命令

1. 在插件目录执行 `npm run deps:check`。
2. 如果提示缺少 `node_modules/.bin/vite.cmd`，说明 `node_modules` 的命令入口损坏。
3. 执行 `npm run deps:repair` 自动修复依赖。
4. 修复完成后重新执行 `npm run build`。

### 构建提示无法解析 hls.js

1. 在插件目录执行 `npm run deps:check`。
2. 如果提示缺少 `node_modules/hls.js/dist/hls.mjs`，说明 hls.js 包安装不完整。
3. 执行 `npm run deps:repair`，脚本会移除损坏的 `hls.js` 目录并重新执行 `npm install`。
4. 修复完成后重新执行 `npm run build`。

### 远程账号池同步失败

1. 检查 Worker 地址是否可访问。
2. 检查 Worker 是否配置了 `SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY`。
3. 检查 Supabase 是否已执行 `schema.sql`。
4. 访问 `/v1/health` 查看必填变量是否齐全。
5. 在「设置」页点击「开始体检」，根据分项检查处理密钥、数据库或账号池问题。

### 云端服务体检分数较低

1. 如果提示缺少密钥，补齐 Cloudflare Secrets 或本地 `.dev.vars` 后重新部署。
2. 如果提示数据库连接异常，确认 Supabase 地址、`service_role` 和 `schema.sql` 是否正确。
3. 如果提示账号池为空，先上传本地账号或调用 `/v1/accounts/seed` 写入种子账号。
4. 如果提示异常账号较多，打开账号池页的「查看失效」并重新上传凭据。
5. 如果提示待验证账号较多，逐个点击账号检查，减少播放时临时轮换等待。

### 本地账号上传云端后显示无凭据

1. 确认插件版本为 `1.3.0` 或更高版本。
2. 当前版本已保留云端摘要中的 `hasPassword`、`hasQrcode`、`hasToken` 标记。
3. 如果旧云端账号仍显示无凭据，重新上传该账号或在 Worker 部署新版后重新同步云端账号池。
4. 云端账号如果确实没有任何凭据，会显示「不可用：账号没有可用凭据」。

### 保存账号后页面刷新

1. 确认插件版本为 `1.3.0` 或更高版本。
2. 当前版本已将添加账号弹窗中的按钮全部改为普通按钮，并拦截表单默认提交。
3. 如果仍然刷新，请检查是否同时启用了旧版本插件。
4. 关闭旧版本插件后刷新页面，再重新打开「账号池」页保存。

### 播放详情为空

1. 确认账号池中至少有一个可用账号。
2. 同步远程账号池后再试。
3. 确认云端账号中至少有一个可用账号。
4. 查看 Worker 日志确认服务端接口是否返回错误。

### 下载按钮没有反应

1. 进入「下载」页点击「刷新下载」。
2. 确认视频详情页上的下载按钮已经渲染完成。
3. 检查浏览器是否拦截下载。
4. 如果任务正在下载 M3U8 分片，请等待显示「合并完成，待保存」。

### 保存到设备没有弹窗

1. 检查浏览器默认下载目录是否可写。
2. 查看浏览器下载记录。
3. 如果希望每次选择位置，请在浏览器下载设置中开启「下载前询问保存位置」。
4. 如果插件显示 TS 兜底，说明 MP4 转封装失败但文件仍可保存。

### 检查更新不灵敏、云端版本比本地旧、或没有检测到新版

1. 进入「设置 → 版本升级」，点击「实时检查」（升级系统 v7，手动操作始终绕过 15 分钟成功缓存）。
2. 检测会同时请求固定仓库路径的多个清单源（GitHub raw、gitmirror、ghproxy、jsDelivr 等），只有通过正式公钥签名的结果才参与 **version/build** 比较；单个 CDN 的旧缓存或被篡改内容不会覆盖有效新版本。
3. 升级中心会显示缓存年龄、镜像成功/失败数量和逐源版本；自动打开面板时命中成功缓存属于正常现象，点击「实时检查」可立即刷新。
4. 远程 `version` 大于本地 `manifest.json` 的 `version` 时会提醒；版本相同但远程 `build` 晚于本地构建时也会提醒。
5. 本地已是最新时：本地版本与远程版本应一致（或本地构建不低于远程）。若仍显示远程更旧，请确认浏览器已重新加载当前插件目录。
6. 如果显示签名失败，请重新执行 `npm run release` 并完整推送 `update.json` 与 CRX；README 不再作为无签名更新依据。
7. 如果显示检测失败，请确认网络能访问上述任一清单源；可点「复制信息」保存升级系统报告后再排查。

### 下载最新版失败

1. 进入「设置」页，点击「检查更新」后再点「下载」。
2. 插件会实时验证 schema 3 签名清单，再按其中被签名的大小和 SHA-256 获取 **CRX3 安装包**（`releases/tangxin-zhizhe-latest.crx`）。
3. 每个候选地址都必须完全匹配固定 owner/repo/branch/path；完整文件还要通过 SHA-256、CRX3 内嵌公钥、正式扩展 ID、ZIP 起点和包自身 RSA 签名校验，任何一项不符都会切换镜像。
4. 高级信息会列出每个镜像的 `validated`、`submitted`、`validation-failed` 或 `submit-failed` 状态和具体错误。
5. 保存文件名形如：`糖心志者_版本号_构建号_最新版.crx`，界面同时显示浏览器下载编号。
6. 如果浏览器拦截下载，请打开浏览器下载记录允许保留文件；CRX 提交下载不等于完成安装，下载后仍需在扩展管理页手动安装或覆盖更新。
7. 如果仍然失败，在升级中心点「复制报告」保存完整镜像与校验结果；主界面不会把未经验证的候选 URL 标成可信安装入口。

### 开发者如何打 CRX 包（发版）

1. 确认本机已安装 Node.js，并在项目目录执行过 `npm install`。
2. 开发源码升级时先同步：`manifest.json`、`package.json`、`package-lock.json`、`ui-src/app/constants.ts`、`background.js` 本地构建号、`preview.html` 和 `README`；没有正式私钥时不要修改 `update.json`、`latest.json` 或 CRX。
3. 正式发版时从离线备份恢复 `keys/txzz-extension.pem`，再把 `update.json` 的版本、构建号和首条日志更新到源码版本；打包脚本会计算安装包哈希并重新签名。除非原私钥确认永久丢失且接受扩展 ID 变化，否则禁止生成替代身份。
4. 执行一键发版构建：

```bash
npm run release
```

该命令会依次执行依赖自检、TypeScript 检查、生产构建、源码身份检查、CRX3 打包、外置清单签名和完整发布校验。最后一步会验证 `update.json` 的固定公钥签名、CRX3 自身签名和正式 ID，解析 ZIP 中央目录并验证 CRC32，再把 CRX 内每个运行时文件与当前工作区逐字节核对；任一项不一致都会终止发版。

5. 产物在 `releases/`：
   - `tangxin-zhizhe-latest.crx`（更新系统固定下载这个）
   - `tangxin-zhizhe-{版本号}.crx`（带版本备份）
   - `extension-id.txt`、`latest.json`、`signing-public-key.json`
6. `keys/txzz-extension.pem` 必须从安全备份准备好且禁止提交。私钥缺失或不对应正式 ID 时打包会直接失败，程序绝不会自动生成替代身份。
7. 将 `releases/*.crx`、签名清单与源码一并提交并推送到 `main`，用户即可在线下载更新。

## 安全与隐私

- 不要把账号密码、二维码凭证、token、deviceId 写入插件源码。
- 不要把 Supabase `service_role` 写入插件源码。
- 插件内置访问密钥只用于识别配套客户端，不承载 Supabase 管理权限；真正的数据库和账号加密密钥仍必须只保存在 Worker 或 GitHub Secrets 中。
- 不要提交 `.env`、`.dev.vars`、日志、截图、浏览器 profile 和运行证据。
- 已经暴露过的密钥应立即轮换。
- 云端账号凭据应由 Worker 加密保存，插件只展示脱敏摘要。
