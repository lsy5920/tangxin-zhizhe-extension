# 沉浸糖果影院播放系统 5.6

本文档描述扩展 5.6.0 的播放架构、Vlog 当前卡片锁定、独立浏览器影院按需开映、合集选集/续播、下载入口、状态边界、线路策略、播放模式、竖屏舞台、手势、持久化规则和验收标准。影院运行于单独的 `cinema.html` 标签页，目标站工作台与既有放映室仍保留；两者共享同一播放控制器和生产样式。页面只负责展示统一 ViewModel，不直接持有 Shaka Player、计时器或购买流程。

## 端到端边界

1. `page_context_core.js` 交叉核对活动 DOM、播放器 ID、Vue `isActive` 与 Swiper 索引；`content.js` 只在上下文锁定后向后台发送 `createPlaybackSession`。
2. `background.js` 为每次请求生成 `requestId`，远程模式只调用 Worker `POST /v2/playback/session`；本地模式使用同等五态购买账本。
3. Worker 返回统一 `session`，其中包含影片、线路、推荐决策、账号摘要、获取方式、缓存时间和过期时间。
4. `screening` 状态保存当前会话、历史和请求步骤；旧 `fullDetails` 首次升级时只迁移一次。
5. React 页面把会话交给 `usePlaybackController`，媒体事件再通过单 reducer 生成界面状态。

## 会话状态机

正常状态流为：

```text
idle → resolving → ready → loading → paused → playing
                                  ↘ buffering ↔ playing
                                  ↘ switching → paused/playing
                                  ↘ ended
                                  ↘ error
```

- 每次会话创建新的 `generation`。`RESET` 先建立代次边界，同代次的 `SESSION_READY` 和媒体事件才可更新状态。
- MediaKernel 的事件回调捕获创建内核时的代次；旧 Shaka、video、全屏和计时器回调不能借用新代次。每次装载最多发布一次 `ready`，装载异常只沿一条串行切线路径进入 reducer。
- 主播放链路任意时刻最多一个 Shaka Player 与一个原生 video。加载新会话前先销毁旧内核；切线在同一适配器内重建媒体实例。后发装载或 `destroy()` 会使仍在 `attach/load` 的旧任务失效，旧实例不能复活。
- 目标帧预览允许一个与主播放隔离的低码率 Shaka 会话：只缓存约 2 秒、限制到 360P/900 Kbps、静音且不写续播；手势结束后保留预热，线路或媒体指纹变化时立即销毁。它不是第二条业务播放链路，也不会触发解析或购买。
- 控制器分别比较会话身份、媒体 URL 指纹和健康元数据修订：同会话新 URL 保留进度与暂停状态后重载，同 URL 只更新元数据。
- 首次资源 `ready` 后固定进入暂停态，只有用户点击「开映」、控制栏、空格/K 或 Media Session 播放动作才调用 `play()`。画面内明确选集和自然结束后的免费/VIP 续播会在新会话 `ready` 后自动播放一次；该意图按 movieId 消费，不能泄漏到其他影片。

## 合集选集与自动续播

- 用户打开影片详情后统一读取并白名单化 `groups` 元数据，以识别缺少 `is_episode` 目录标记的合集；普通影片只有父项，不显示选集。该检测不进入完整线路、账号轮换或购买流程。
- 播放器从当前 `cinemaCollection` 计算当前集索引和下一集；视频画面直接提供「选集 X/Y」，选中后重新调用 `openCinemaPlayback`，绝不复用上一集签名 URL。
- 新分集会话仍经过账号、线路、健康度与购买账本流程。旧媒体的 `ended / error / pause` 事件由 generation 隔离，不能触发新集续播。
- 只有原生 `ended` 状态可启动下一集；暂停、拖动、缓冲、致命错误和手动换线均不触发。
- 免费/VIP 下一集在自然结束后显示 5 秒倒计时并续播；用户可取消本次倒计时或关闭当前播放页的自动续播。
- 金币下一集永远不自动进入检票，覆盖层显示价格并要求再次点击确认，避免把连续观看意图解释成默认扣费授权。
- 切集会清理临时 A-B 循环、拖动预览、长按倍速和旧倒计时；收藏、书签与按 movieId 保存的续播记录彼此独立。

## 线路策略

- URL 为空或服务端明确标记失败的线路直接淘汰；健康线路优先，同分时主线路优先。
- Worker 在返回会话前并行探测主备 HLS；主清单没有 `EXTINF` 时继续解析最多四个变体清单。两条可用线路覆盖时长的差值同时超过 90 秒和短线路的 8% 时，优先选择较长线路，避免短预览线凭低延迟或主线身份覆盖完整版；阈值是相对规则，不依赖某个视频的固定时长。
- 扩展本地账号模式复用相同探测与相对时长规则；旧缓存若已记录主备时长，会在加载时自动纠正推荐线路。无扩展名地址使用有限 Range 探测，明确的大型 MP4 不会被完整下载。
- 用户首次播放后启动 8 秒起播保护；超过 8 秒仍未进入 `playing` 时尝试下一条未自动尝试的线路。
- Shaka 在 30 秒内累计 3 次致命错误时切线。网络恢复与媒体恢复按线路分别各尝试一次；恢复后 4 秒仍未播放则切线。
- 稳定播放 10 秒会清空致命错误和恢复使用标记。
- 每条线路每个会话只允许自动尝试一次，`attemptedSourceIds` 阻止主备反复跳转；没有候选时进入明确错误态。
- 切线保留当前时间、暂停/播放状态、音量、静音、倍速和画面填充模式。用户暂停时发生自动切线，备用线仍保持暂停。

## Vlog 当前卡片锁定

- 活动 DOM、播放器绑定 ID、Vue `isActive` 与 Swiper 当前索引共同投票；`playerInfo` 只有在与高置信证据一致时才可补充标题等信息。
- 旧 ID → 空值 → 新 ID 的空窗只进入 `transitioning`，保留最后一个稳定非空 ID，但不会把空值当成旧请求的通配符。
- 每次稳定换片递增页面代次；旧代次的 Worker 响应、原生播放器回填、下载和复制动作都不得写入当前卡片。
- Vue 2 `__vue__` 只对页面主世界可见；`page_hook` 在初始、ID、`transitioning`、epoch 变化时发布带单调 `contextRevision` 的权威快照。`content.js` 不再二次读取 Vue，只校验当前 URL、movieId、epoch 和 revision。
- 网站播放器、插件播放器、复制链接和下载统一消费 `session.decision.recommendedSourceId`。当前卡片核对、线路探测和失配诊断仅在后台及插件工作台内维护，不再向网站左上角注入电影票 HUD。

## 省流 / 均衡 / 高清模式

- `balanced` 为默认：启用 ABR，并按播放器尺寸限制不必要的超高分辨率。
- `data-saver`：限制到 720P 与约 2.5 Mbps；用户主动选择始终优先于 Network Information API。
- `high-quality`：允许设备支持的最高档，但缓冲不足 5 秒时仍可自动降档，质量面板会展示线路、码率、缓冲量和降档原因。
- 模式按设备持久化，切线、全屏、同会话 URL 更新和断点续播不会重置。

## 续播与偏好

- 续播记录按 `movieId` 存储，每 5 秒以及暂停、页面隐藏时写入。
- 当前时间小于 15 秒、距结尾不足 30 秒、总时长无效或记录超过 30 天时不恢复。
- 音量、静音、倍速、亮度、填充、比例、方向、快进步长和标准/镜像手势独立持久化；偏好变化不销毁当前媒体内核。
- Wake Lock 的异步取得结果会复核会话代次；若播放器已暂停、结束或销毁，迟到的锁会立即释放。

## 竖屏舞台、菜单与手势

- 舞台方向按“用户明确偏好 → video 真实尺寸 → HLS 变体 → 横屏回退”决定。9:16 视频仍以 `object-fit: contain` 完整显示，但内嵌黑色影院画布受动态视口高度约束，不再按原始 9:16 比例把页面无限撑高。
- 设置菜单固定为“片源 / 观看 / 工具”三类。线路、清晰度和网络策略归入片源；倍速、跳转步长、画面、亮度、音量和手势归入观看；重载、画中画、截图、全屏校准和诊断归入工具。复制、打开保留在片源抽屉；下载保留画面快捷入口、影片侧栏和下载抽屉，三处都进入同一个规划器而不是复制业务；静音只保留在主控制栏。
- 标准手势为左侧双击/长按快退、右侧双击快进与长按 3x；镜像手势为左侧双击快进与长按 3x、右侧双击/长按连续快退。
- 横向滑动不参与镜像：始终左划回退、右划前进。横滑和直接拖动进度条使用同一个受控预览值；主播放器在整个手势期间暂停并固定于起点，进度点与小画面立即跟随，只有松手才向主播放器提交一次正式 seek，`pointercancel` 则恢复起点与原播放状态。
- 目标帧优先读取 Shaka 识别到的 HLS Image Playlist、I-frame 或 WebVTT 缩略图轨。目标站没有缩略图轨时，由独立 360P 预览器按 90ms 合并最新目标并解码对应分片；过期请求被丢弃，预览 CDN 首次失败可重建一次，主视频当前帧 Canvas 负责即时兜底。这个流程复用同一条已签名线路，不重新解析、不购买，也不修改 Media Session 或续播点。
- 会话、媒体 URL 或线路代次变化时立即取消旧长按、横滑、HUD 和临时倍速，旧手势不能作用到新影片。

## 本地购买防重复语义

本地账号模式在 `chrome.storage.local` 保存 `pending / charged / resolved / failed_before_charge / uncertain` 五态账本：

- 任意账号已经返回主线或备用线时立即返回直链，禁止购买。
- 只在全部可用账号均无直链时，从最低金币账号组随机选一个。
- `doBuy` 成功后先写 `charged`，再刷新详情；刷新失败写 `uncertain`，后续只能用原账号对账。
- `charged` 或 `uncertain` 不允许自动选择第二个账号购买；只有已确认的购买前失败才允许尝试下一账号。
- 设置页对账中心只允许原账号重新获取详情，不调用 `doBuy`，也不提供直接清除安全阻断；成功写 `resolved`，失败继续保持 `uncertain`。

## 自动化与真实扩展验收

仓库不再提供 `preview.html`、模拟 `chrome.*` 桥或本地场景页。Vitest 只负责 reducer、迁移、线路、手势方向、舞台方向、下载与签名等纯核心回归；所有视觉、交互、媒体和扩展 API 验收均使用 Vite 生产产物，在完整 CDP 权限的 Chrome 开发版中安装未打包扩展后执行。

发布前必须通过 TypeScript、全部 Vitest、生产构建、源码门禁、CRX3 内容/签名门禁，并在真实 `chrome-extension://` 运行环境检查页面与 Service Worker 控制台。

## 视觉与响应式验收

- 桌面 `1440×900`：主舞台与影片侧栏双栏，抽屉位于下方。
- 移动 `390×844`：单栏、底部安全区导航、播放器控制不横向溢出。
- 横屏 `844×390`：侧栏导航与内容独立滚动，播放器仍可进入铺满兜底。
- 宽度 `320 / 640 / 1024 / 1536`：页面、主滚动区和播放器均不得出现横向溢出。
- 播放时隐藏星光等干扰装饰；视频舞台保持纯黑高对比，奶油粉紫只用于外壳和状态。
- 全屏故障场景下，主舞台、媒体容器和 video 都必须覆盖整个视口；退出后不得残留 `txzz-player-fullscreen-mode` 或 `data-txzz-fs-forced`。
